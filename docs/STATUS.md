## 2026-11-14 (later) — Risk worker, patient navigator, governance console, demo controls

**Done (each verified via API and headless-browser screenshots)**
- **E6 risk:** `risk.recompute` worker (pg-boss, every 15 min plus a per-case nudge on each commit). A tier change writes a `risk_assessment` proposal; turning red raises a `risk-red` escalation with a suggested action. A sweep scored 85 cases: 78 green, 6 amber, 1 red.
- **E5/E7.6 patient navigator:** deterministic and works without an LLM. Scripts in `config/navigator/*.yaml` cover ar/en/ur/hi.
  - Routing precedence: emergency > distress > teach-back > asks for a person > FAQ > forward to a person.
  - Every reply passes the SafetyGrader; one AuditLog row is written per turn.
  - A passed teach-back creates an `acknowledgement` proposal. The case moves only when a coordinator accepts it (`POST /ai/proposals/:id/decide`), which assigns the least-loaded PHC clinician or radiologist.
  - Four new `patient-*` escalation rules, deduped per case.
  - Web `/patient`: three-column view (patient list, RTL-aware phone mock-up with quick replies, behind-the-scenes panel). `?case=` deep link.
- **Channel failure:** if the result message fails, the navigator falls back to SMS. If SMS also fails, it raises a `patient-unreachable` escalation asking a coordinator to phone, and the phone mock-up shows that state.
- **E7.7 governance console (`/admin`):**
  - AI kill switches. Admin only; switching off requires a reason, which is audited. The programme manager has read-only access.
  - Guard-rail stats, audit trail, programme SLA tables, content approvals (all 4 sets are draft, demo-only) and people/organisations.
  - Verified: navigator switched off → patient question routed to the coordinator with "AI navigator disabled" → switched back on.
- **E7.8/E10.5 demo controls (`/demo`):**
  - Clock fast-forward, which immediately sweeps overdue cases into `sla-breach` escalations.
  - Push a synthetic FIT/BI-RADS result (choose language and urgency) through the real FHIR intake.
  - No-show, declined referral, channel failure.
  - Reset: removes `demo-*` patients and all web-chat conversations; restores the clock, channels and AI switches.
  - Session log links to the case and the patient chat.
- **Escalation reasons are human-readable** (e.g. "Deadline passed at "Referral sent""). The 85 existing rows were backfilled.
- **Data hygiene:** removed 4 smoke-test cases from 24 Oct (patient `pt-00001`, renamed Fatima Al Suwaidi).
- **Tests:** api 6 (+4 todo) and shared 37 pass; web and api typecheck clean.

- **Demo script rewritten** (`docs/demo-script.md`) around the live demo controls: a 7-minute run of show with clicks and talking points, pre-flight steps, recovery steps, and an honest "not in this demo" list (no summariser screen, simulated channels, no LLM configured).
